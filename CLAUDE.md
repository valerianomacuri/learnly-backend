# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

FastAPI + async SQLAlchemy 2 + PostgreSQL API template providing authentication (JWT + Argon2id passwords) and RBAC (users, roles, permissions) only; domain entities are added on top. Python 3.13, managed with `uv`. See `README.md` for env vars and production build steps.

## Commands

```bash
uv sync                                          # install deps
cp .env.example .env                             # DATABASE_URL and JWT_SECRET are required
docker compose up -d db redis                    # PostgreSQL + pgvector (also creates customer_support_test DB) + Redis (spec 12)
uv run alembic upgrade head                      # migrate
uv run seed                                      # dev data, the 13 refund edge cases + printed JWTs (idempotent; --reset, --no-tokens); refuses ENVIRONMENT=production
uv run uvicorn app.main:app --reload --app-dir src

uv run pytest                                    # all tests
uv run pytest tests/test_flow.py::test_name      # single test
uv run ruff check . --fix && uv run ruff format .
uv run mypy                                      # strict mode

uv run alembic revision --autogenerate -m "msg"  # review output; migrations/versions is excluded from ruff
uv run alembic check                             # models vs. migrations drift
```

- DB-backed tests need Postgres and **skip** (not fail) if it is unreachable. The `session_maker`/`client` fixtures in `tests/conftest.py` drop and recreate the schema with `Base.metadata.create_all` for every test, so tests don't exercise Alembic migrations; override the DB with `TEST_DATABASE_URL`. Other fixtures: `make_user(RoleName, extra_roles=, email=)` inserts a user with its roles and a pre-computed password hash (Argon2 is slow) and returns `Actor(id, headers, email, password)`. Domain fixtures: `make_course(...)` -> course id, `make_purchase(customer, days_ago=, progress=, certificate=, payment_method=, purchase_type=, status=, ...)` -> `PurchaseRef` (with its progress row) and `make_refund(purchase, status=, ...)` -> refund id. Test modules import helpers with `from conftest import ...`.
- Windows: psycopg async needs `SelectorEventLoop`. Without `--reload`, pass `--loop asyncio:SelectorEventLoop` to uvicorn. The tests already supply it via `pytest_asyncio_loop_factories`.
- Settings are validated at import time (`app = create_app()` in `main.py`), so importing `app.main` without a valid `DATABASE_URL` and `JWT_SECRET` fails. `conftest.py` sets the env vars before importing app modules.

## Architecture

Layered, with a strict one-way dependency: `api/routes` → `services` → `repositories` → `models`. `schemas/` (Pydantic DTOs) are used at the route and service boundary.

- **Wiring**: `api/deps.py` builds a service per request from the request-scoped `AsyncSession`. Each service constructs the repositories it needs from that same session, so all work in a request shares one transaction.
- **Transactions**: `core/database.get_session` commits once at the end of a successful request and rolls back on any exception. Repositories only `flush` (see `BaseRepository.add`) and never commit. Services mutate ORM objects and flush; don't commit inside them.
- **Errors**: services raise `NotFoundError` / `ConflictError` / `ForbiddenError` / `InvalidInputError` (`services/errors.py`). `main.py` maps them to 404 / 409 / 403 / 422 JSON, so routes don't catch them. Add new domain errors there and register a handler. Raising rolls the request transaction back, so an outcome that must persist (e.g. a failed login) is **returned**, not raised (see `AuthService`).
- **Auth / RBAC**: every route except `/health` and `/healthz` needs a JWT bearer (`core/security.py`) whose only claims are `sub` (the `User.id`), `iat` and `exp`. Roles and permissions are read from the database on every request (`UserRepository.get_principal`: `users` ↔ `user_roles` ↔ `roles` ↔ `role_permissions` ↔ `permissions`, both many-to-many), so changing a role takes effect without a new token; an unknown user is 401. The catalog (roles `customer` / `supervisor`, permissions `<resource>:<action>` such as `user:read_any`) lives in `core/permissions.py` and is written to the tables by `services/rbac.ensure_rbac` (seed and tests). Routes receive a `Principal` through `PrincipalDep` or the `requires(Perm.X)` guard (`api/deps.py`) and pass it to services; services re-check with `require_permission` / `require_any_permission` (`services/authz.py`). `POST /api/v1/auth/login` (`api/routes/auth.py`, `services/auth_service.py`) exchanges email + password for a token; passwords are Argon2id hashes (`core/passwords.py`, `users.password_hash`), never returned (`UserRead` has no password field), and a wrong password or unknown email give the same 401 (dummy-hash verify for timing) and a failure that is *returned, not raised*. Password fields are `SecretStr` and are not whitespace-stripped (`schemas/user.py`, `schemas/auth.py` turn `str_strip_whitespace` off). A pre-password user holds `UNUSABLE_HASH` (`!`) and cannot sign in. `create_access_token` is also used by the seed and tests.
- **Owner scoping**: there is no tenancy. Resources belong to a `User`. `repositories/scope.restrict(stmt, principal, Perm.X_READ_ANY)` lets a caller holding the `*_any` permission see every row and limits everyone else to rows they own. Out-of-scope rows behave like missing rows (404). Never fetch by id alone in a service that serves a caller; use `get_scoped`.
- **Repositories**: subclass `BaseRepository[Model]` and set `model`. It provides get/list/add/delete, and entity-specific queries go in the subclass.
- **Models**: `models/base.py` holds the constraint naming convention (needed for Alembic autogenerate), `IdMixin` (UUID pk), `TimestampMixin`, and `str_enum`, which stores enums as VARCHAR + CHECK rather than native PG enums. Use `str_enum` for new status columns.
- **Entities**: `User` (unique email; roles via `user_roles`), `Role`, and `Permission`, plus the refund domain, one file per aggregate in `models/`: `Course`; `Purchase` + `CourseProgress`; `RefundRequest`, `RefundEvent`, `RefundInternalNote`, `RefundPayout`, `CreditLedgerEntry`; `EligibilityCheck`; `OutboxEvent`; `ChatThread`; `PolicyDocument`. Their enums live in `domain/enums.py` (pure) and are stored with `str_enum` (max 20 chars). Database-level guarantees: a trigger makes `refund_events` append-only (defined in `models/refund.py` through `DDL` so `create_all` gets it, and by hand in migration 0002); a partial unique index allows one active request (`ACTIVE_REFUND_STATUSES`) per purchase; `UNIQUE(customer_id, idempotency_key)`; `reason_text` length CHECK. `refund_events.created_at` uses `clock_timestamp()` so events of one transaction keep their order. `RefundEventService.append` is the only way to write events. `refund_internal_notes` and `refund_events.payload` are never serialized in customer schemas.
- **Purchases**: `PurchaseRepository` has no `*_any` scope: only the owner reads a purchase (a supervisor sees it through the refund detail, spec 04), and someone else's purchase is a 404 identical to a missing one. `PurchaseService` takes an injectable `clock` and paginates with the opaque `(purchased_at, id)` keyset cursor of `core/pagination.py`. The refund window comes from the active `PolicyConfig` (`refund_window_days`). Money is `Decimal` in Python and a JSON number in responses (`schemas.purchase.Money`).
- **Seed**: `cli/seed.py` creates courses and the 13 cases of challenge §9 (`CASES`: structured expectations that spec 02 reuses as a fixture). Dates are relative to `now()` (`seed(..., now=)` is injectable) and are re-computed on every run. `ann` is the owner of most cases (the challenge's "cust1"), `bob` owns the foreign purchase, and the cases that need refund history use their own customer. `--reset` lifts the append-only trigger only inside its own transaction to delete seed events.
- **Domain packages**: `domain/` holds pure business logic and must not import SQLAlchemy, FastAPI or `app.services` (enforced by `tests/unit/test_architecture.py`). `agent/` (spec 09) may use services but never `fastapi`/`app.api` (same test).
- **Policy & eligibility**: `policies/*.md` front-matter is the single source of the thresholds. `uv run policies-load` (`app.policy.load`, idempotent by checksum, atomic activation) fills `policy_documents`; `PolicyRepository.get_active_config()` builds the frozen `PolicyConfig` (cached by checksum fingerprint) and the lifespan of `create_app` fails if no complete ACTIVE policy exists (`seed` and the test `session_maker` load it too; dir override `POLICIES_DIR`). `domain/eligibility.py` holds the pure `RefundPolicyEngine` (BR-01...BR-10, injected clock, accumulates all `reason_codes`); `EligibilityService.check` gathers the facts, always writes an `eligibility_checks` row and serves `GET /purchases/{id}/refund-eligibility` (customer schema `EligibilityRead` omits `warnings`; foreign == missing purchase, both 200 `PURCHASE_NOT_FOUND`).
- **Refund creation (spec 03)**: `RefundService` (`services/refund_service.py`) is the single entry point (`preview`, `create_request`, `cancel`, reads); `domain/` has `state_machine.py`, `confirmation.py` (HMAC token over `payload_hash`) and `reason.py` (BR-12). Domain rule violations subclass `domain.errors.DomainProblem` (`code`, `status`, `reason_codes`) and `main.py` renders them as `application/problem+json` with `trace_id` (the `X-Request-ID` middleware); the older `NotFoundError`/`ConflictError`/... handlers keep the `{"detail"}` format (not migrated). **Failed attempts persist**: `create_request` flushes the `eligibility_checks` row and raises `RefundNotEligible`; the `POST /refunds` route catches it and *returns* the 422 so `get_session` commits (the other `DomainProblem`s raise and roll back). **Idempotency**: `request_hash` (sha256 of purchase, reason; not the token) next to `UNIQUE(customer_id, idempotency_key)`; the purchase row is locked `FOR UPDATE` first, so concurrent duplicates wait and replay the original (201 again); same key + other body is 409 `IDEMPOTENCY_CONFLICT`; an `IntegrityError` on insert (inside a savepoint) re-reads by key. Event types are `REFUND_*` strings; only `PUBLIC_EVENT_TYPES` reach the customer timeline.
- **Supervisor API (spec 04)**: `SupervisorRefundService` (`services/supervisor_refund_service.py`, injectable `clock` and `sla_hours`) serves `api/routes/supervisor.py` (`/supervisor/*`, every route behind `requires(...)`: `refund:read_any`, `refund:decide`, `note:read|write`) over `repositories/supervisor_refund.py` (no owner scoping; authorization is the service's job) and `refund_note.py`. Its schemas (`schemas/supervisor.py`) never reuse the customer ones. `_decide` checks in this order: permission, row lock (`FOR UPDATE` + `populate_existing`), self-approval 403 `SELF_APPROVAL_FORBIDDEN` (BR-20), status 409 `REFUND_NOT_PENDING` (BR-17), `If-Match` 409 `VERSION_CONFLICT` (BR-18), rejection note >= 10 chars 422 `DECISION_NOTE_REQUIRED` (BR-19); the lock makes the loser of a race re-read the decided row and get the 409. `If-Match` is parsed in the route (428 `IF_MATCH_REQUIRED`, 400 `INVALID_IF_MATCH`). `sla_breached` is a query clause (`PENDING_APPROVAL` and `created_at < now - sla`), never stored; `high_risk` is a JSONB containment on the snapshot's `warnings`. The queue sorts by `created_at`, `amount` or `sla` (= oldest first) with a keyset cursor `(value, id)` (`core/pagination.encode_keyset`). Internal notes: the `NOTE_ADDED` event is internal because it is not in `PUBLIC_EVENT_TYPES` (the customer timeline filters by type) and its payload holds the note id, never the text. Emails are masked with `core/privacy.mask_email` in every supervisor response. `approve` changes state, writes the event and, in the same transaction, the `refund_payouts` row and the `refund.payout` outbox event; `retry_payout` (`FAILED -> PROCESSING`, 409 `REFUND_NOT_FAILED`) re-enqueues. The seed adds two customers (`carol`, `erin`) with `QUEUE_REFUNDS` in several states and ages for the dashboard.
- **Payout worker (spec 05)**: `workers/payouts.py` (`PayoutWorker`, entry point `payouts-worker`, `--once`; injectable `clock`, `WorkerConfig`) claims outbox events with `FOR UPDATE SKIP LOCKED`, one transaction per event. Gateway port + `SimulatedGateway` (idempotent per key, `failures=`/`FAIL_RATE`) in `workers/gateway.py`. BR-23 effects run inside a savepoint (purchase `REFUNDED` + `access_revoked_at`, ledger credit only for `PLATFORM_CREDITS`; `credit_ledger.refund_id` is unique); a failure there is recorded like a transient one. Retry counters live in `refund_payouts.attempts/last_error`; backoff `base * 2^(n-1)`, max 3, then `FAILED` + outbox `DEAD`. Customer `RefundRead.payout` shows only status/method/amount; the supervisor detail adds attempts, error and provider ref.
- **Frontend base (spec 06)**: `GET /policies` (summaries) and `/policies/{doc_key}` (ACTIVE version + Markdown) serve `policy_documents.title/content`, filled by `policies-load` (rows loaded before migration 0005 are backfilled on the next run). `RefundEventService.append` also `pg_notify`s channel `refund_events` (`{event, id, status, version}`), delivered on commit; `GET /supervisor/refunds/stream` (`services/refund_stream.py`) is an SSE over one dedicated psycopg `LISTEN` connection per client (heartbeat `SSE_HEARTBEAT_SECONDS`, `Cache-Control: no-store`); its guard uses `Depends(..., scope="function")` so the request session is released before streaming. CORS origins come from `CORS_ORIGINS` (comma-separated). The React app lives in `../learnly-frontend`.
- **RAG (spec 07)**: `rag/` is the pipeline over `policy_chunks` (pgvector HNSW cosine + generated `tsvector`; migration 0006; `embedding_model/dim` on `policy_documents`). `chunking.py` (structural by heading, H1 dropped from `section_path`, tables/lists/FAQ pairs atomic, `fixed_500` alternative), `embeddings.py` (`Embedder` port, `OpenAIEmbedder`, deterministic `FakeEmbeddings` for tests), `ingest.py` (`uv run rag-ingest`; no-op when checksum, strategy and embedding model match; embeds first, then activates + replaces chunks in one transaction), `retriever.py` (dense + lexical top-20, RRF, optional cross-encoder, parent expansion, relevance gate -> `insufficient_evidence`), `answer.py` (`PolicyAnswer`, number check against `PolicyConfig` + retrieved context, LLM grounding judge, abstains with `needs_handoff`), `llm.py` (`ChatModel` port, `FakeChatModel`), `ask.py` (`python -m app.rag.ask`). `reason_map.citations_for` gives deterministic citations from `PolicyConfig.reason_code_map` (values are `<label> > <section_path>`; chunks store the part after the label; `unqualify` strips it) and feeds `RefundService.preview` and the supervisor detail, so they never need the LLM or embeddings. Settings: `OPENAI_API_KEY` (optional), `EMBEDDING_MODEL`, `EMBEDDING_DIM`, `LLM_MODEL`, `RELEVANCE_THRESHOLD`, `RERANK_MODEL`. `rag/` must not import FastAPI or `app.services`. Tests: `tests/rag` (`ingested` and `embedder` fixtures live in the root `conftest.py`); `-m live` is excluded by default (`addopts`).
- **RAG evals (spec 08)**: `rag/evals/` scores the pipeline against `tests/rag_evals/golden.jsonl` (79 questions; `expected_sections` entries may list equivalent sections as `A || B`). `metrics.py` is pure; `judges.py` has `LLMJudge` and a lexical `HeuristicJudge`; `fakes.py` the offline `ExtractiveChatModel`; `runner.py` rebuilds the `*_evals` database (name must contain `eval`; `EVALS_DATABASE_URL` or `<DATABASE_URL db>_evals`, created on demand), ingests with the chosen strategy and asks every question; `report.py` prints the table and writes `reports/rag-evals-<date>-<strategy>-<mode>.json|md` (git-ignored). Thresholds live in `evals/thresholds.toml` (`[full]` real bar, `[offline]` only recall of lexical retrieval, figures and poisoned leaks); exit code 1 if one fails. `python -m app.rag.evals.run [--offline] [--strategy structural|fixed_500]` (`make rag-evals`, part of `make evals`). The poisoned corpus (`tests/rag_evals/poisoned/`) is ingested next to the real policies. `PolicyAnswerer(..., trusted_figures=)` (`PolicyRepository.get_trusted_figures`: integer front-matter params of the ACTIVE docs) makes the figure check ignore numbers that only appear in a chunk body, so an injected "90 días" cannot pass; `ask` and the evals pass it. The `live` tests are `tests/rag_evals/test_rag_evals_live.py` (excluded by default).
- **Read-only agent (spec 09)**: `agent/` is a LangGraph graph (`graph.py`: `entry_router` -> `guard_input` -> `classify_intent` -> `policy_qa` | `refund_status` | `collect_refund_info` | `cancel_refund_flow` | `handoff` -> `guard_output` -> `respond`; one module per node in `nodes/`). Identity is injected, never asked of the model: the API puts `user_id`, `role`, `thread_id`, `request_id` in `config["configurable"]` (`AgentRuntime.config`), `AgentPrincipal.from_config` reads them and `to_service_principal()` yields a `core.Principal` limited to `AGENT_PERMISSIONS` (purchase/refund read_own, policy:read, refund:simulate). `SupportState` has no customer id; per-turn fields are reset in `entry_router`, and only `respond` writes the assistant message, after `guard_output` (so streamed tokens are already filtered; raw LLM tokens are not forwarded). Tools (`agent/tools/`, one `ToolSpec` each: Pydantic args with `extra="forbid"`, async handler over the existing services, `run_tool` returns `ToolResult{ok,data,error{code,message,retryable}}` and never raises; each tool opens its own session from `ToolContext.session_maker`). `tools/registry.py` holds `ALL_TOOLS` and the explicit `LLM_BOUND_TOOLS` allowlist (the `refund_status` ReAct loop, `tool_budget=6`, refuses names outside it); `tests/agent/test_tool_registry.py` fails if a tool takes `customer_id`/`role` or the registry grows an approval/payment/notes tool. `agent/llm.py`: `get_chat_model()` (LangChain `ChatOpenAI`, T=0, `LLM_TIMEOUT_S`, `LLM_MAX_RETRIES`), scriptable `FakeChatModel` (`script`, `structured`) and `LangChainChat`, which adapts it to the `rag.llm.ChatModel` port so `PolicyAnswerer` is reused (its calls are synchronous). The classifier falls back to `nodes/keyword_classifier.py` after 2 failures. `escalate_to_human` sets the thread `NEEDS_HUMAN` and logs `app.agent.audit` (`refund_events` needs a refund, so it is not used). API (`api/routes/chat.py`, `chat:use`, foreign thread = 404): `POST/GET /chat/threads`, `GET /chat/threads/{id}/messages` (history from the checkpointer via `AgentRuntime.history`), `POST .../messages` (SSE `token|tool_call|tool_result|final|error`, `agent/sse.py`, `stream_mode=["updates","custom"]`). `AgentRuntime` lives in `app.state.agent_runtime`: built in the lifespan by `start_runtime` (AsyncPostgresSaver on its own psycopg pool, `setup()` at startup) only if `OPENAI_API_KEY` is set, otherwise the chat answers 503. Tests build a runtime with `InMemorySaver` (`tests/agent/agent_helpers.py`, no conftest there) and assign it to `app.state.agent_runtime`; the live test is `tests/agent/test_agent_live.py`.
- **Refund flow with HITL (spec 10)**: the graph adds `collect_refund_info` (structured extraction over the candidates of tool 2; the id is verified against them and tool 3; BR-12 via `domain.reason`; sets `awaiting` and asks when something is missing; every turn passes `guard_input`, then `route_guard` sends `awaiting` turns to the flow) -> `check_eligibility` (tool 4) -> `explain_ineligible` (deterministic `citations_for` + narration) | `prepare_confirmation` (tool 5 through `tools.eligibility.prepare`: builds the card in state; the signed token and hash live in separate state keys, never in a card or message) -> `request_confirmation` (`interrupt(card)` is its first statement; it re-executes on resume, so it has no effects; resume `{interrupt_id, decision: confirm|cancel|edit, edited_reason?}`; expired -> `check_eligibility`, new card) -> `create_refund` (tool 6, args from state, `Idempotency-Key = sha256(thread_id + hash)`, `channel=CHAT`, `actor_type=AGENT`; a 422 is returned as data after committing the failed check). Cancel: `cancel_refund_flow` -> `request_cancel_confirmation` (interrupt) -> `cancel_refund_apply` (tool 9, `If-Match` = version, `RefundService.cancel(actor=AGENT)`). Tools 4-6 and 9 are never in `LLM_BOUND_TOOLS`; `create_refund` and `cancel_refund_apply` have a single inbound edge (tested). `AGENT_PERMISSIONS` now includes `refund:create` and `refund:cancel_own`, used only by those nodes. API: `POST /chat/threads/{id}/resume` (SSE; 409 `INTERRUPT_NOT_PENDING`), `GET .../pending-interrupt` (200 card | 204), `POST .../messages` with a pending card is 409 `INTERRUPT_PENDING` (card in `interrupt`), `GET .../messages` appends a trailing assistant entry with `interrupt` when one is pending; SSE adds the `interrupt` event. `AgentDeps.clock` is injectable for the expiry check. Tests: `tests/agent/test_hitl.py`, `test_write_tools.py`, `tests/test_chat_hitl_api.py`.
- **Security & resilience (spec 12)**: `core/redis.py` (`open_redis`, `ThreadLock`: one graph run per thread, 409 `RUN_IN_PROGRESS`) and `core/rate_limit.py` (`SlidingWindowLimiter`, one Lua script over a ZSET using Redis' clock). `api/deps.rate_limit(name, limit, window_s, write=True)` is a route dependency: 429 `RateLimited` (+ `Retry-After` added in `problem_response`); **no `REDIS_URL` = limits off; Redis configured but failing = reads fail open, writes 503 `RATE_LIMIT_UNAVAILABLE`**. Applied to chat `messages`+`resume` (shared counter `chat`, 20/min) and `POST /refunds` (5/h); `app.state.redis` is set in the lifespan (tests assign it; fixtures `redis_client` / `broken_redis` live in the root conftest, marker `redis`). Guardrails live in `agent/guardrails/`: `injection.assess` (strong patterns block; weak ones go to a cheap LLM judge `InjectionVerdict`, which trusts the heuristics if the LLM fails), `pii.mask_pii` (email, card, phone, tokens), `output.filter_output` (internal notes, recited system prompt, supervisor ids, emails); `nodes/guard_input.py`/`guard_output.py` are factories over `AgentDeps` (`guard_output` also checks day/% figures against `PolicyConfig` + trusted figures). Untrusted text (customer messages, RAG chunks) is wrapped by `core/untrusted.wrap_untrusted`/`defang` in `<untrusted>`; `collect_refund_info` drops a model-extracted `reason_text` that looks like an injection. `core/privacy.RedactingFilter`/`install_log_privacy()` mask emails and tokens in all log handlers. `agent/resilience.py`: `CircuitBreaker` (closed/open/half-open, in memory), `Resilience` (retry + backoff + fallback) and `ResilientChatModel` (`get_chat_model()` builds it; `bind_tools`/`with_structured_output` return a guarded runnable); an outage raises `LLMUnavailableError` -> SSE `error{code:"LLM_UNAVAILABLE"}` (`classify_intent` re-raises it instead of falling back to keywords). `agent/budget.py`: `UsageCallback` (sums `usage_metadata`, attached to the run config in `AgentRuntime._run`) and `TokenBudget` (Redis `INCRBY`, memory fallback) -> SSE `error{code:"TOKEN_BUDGET_EXCEEDED"}` before the next turn. `policy_qa` catches `SQLAlchemyError`/`EmbeddingsUnavailableError` (vector store down) and answers `POLICY_STORE_DOWN` offering a person. The payout worker logs `event=payout_dead ...` at ERROR on dead-letter. Tests: `tests/security` (`permissions_table.py` is the living table of who may call each route; `test_route_inventory.py` reads the OpenAPI paths and fails on a route without an entry; `test_bola.py` = 401 without token, 403 wrong role, foreign resource == missing resource; `test_rate_limit.py`, `test_privacy.py`), `tests/agent_evals` (`adversarial.jsonl`, 46 cases, obedient worst-case LLM: zero writes, no leaks), `tests/agent/test_guardrails.py`, `test_resilience.py`.
- **Audit**: `refund_events` is the only audit trail; don't add other audit tables.
- **Specs**: feature work is specified in `docs/specs/NN-*.md` (index in `docs/specs/README.md`); implement them in order and tick their tasks.
- **Settings**: `core/config.py` (`DATABASE_URL`, `JWT_SECRET`, `ACCESS_TOKEN_TTL_MINUTES`, `CONFIRMATION_SECRET` (defaults to `JWT_SECRET`), `CONFIRMATION_TTL_MIN`, `SLA_HOURS`, ...). Policy thresholds are not settings; they come from the policy front-matter.
- **Makefile**: `make check` runs lint, typecheck, tests and evals (needs `make`; on Windows without it run the `uv run` commands above).
